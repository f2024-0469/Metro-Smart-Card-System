# Metro Smart Card System — Measured vs Claimed Performance

## Method

Measurements were taken from the program's built-in `time_us` and `steps` output. The full dataset contains 50,000 cards and 250,000 journeys. For the card-registry scaling check, fresh copies containing 5,000, 25,000, and 50,000 cards were used.

Microsecond values are environment-dependent and are therefore used as observed evidence rather than as a theoretical guarantee. The `steps` counter is the stronger comparison for the data-structure claim.

## Scaling results for card and blocked-card lookup

| Data size | Card lookup median µs | Card lookup median steps | Blocked lookup median µs | Blocked lookup median steps |
|---:|---:|---:|---:|---:|
| 5,000 | 0 | 2 | 0 | 3 |
| 25,000 | 0 | 2 | 0 | 2 |
| 50,000 | 0 | 2 | 0 | 2 |

The measured card lookup stayed at 2 steps in all three runs, matching the intended average O(1) behavior of the custom hash table.

## Representative full-data operation measurements

One fresh run on the complete dataset produced the following values:

| Operation | Claimed complexity | Observed time (µs) | Observed steps |
|---|---|---:|---:|
| Card lookup | O(1) average | 1 | 2 |
| Blocked-card lookup | O(1) with bounded blocked set | 1 | 2 |
| Tap-in | O(1) average | 54 | 7 |
| Tap-out | O(1) average lookup + O(1) fare | 14 | 19 |
| Top-up | O(1) average | 3 | 4 |
| Undo one top-up | O(1) per undo | 0 | 3 |
| Queue enqueue | O(1) | 2 | 1 |
| Queue dequeue | O(1) | 0 | 1 |
| History back | O(1) | 0 | 1 |
| History forward | O(1) | 0 | 1 |
| History delete with node pointer | O(1) | 2 | 1 |

## Advanced A

The daily transaction log uses an append-only dynamic array. Appending is O(1) amortised. Replay is one sequential pass, O(k), where k is the number of transactions in the day's log. The functional test replayed the three transactions generated by the smoke script in their original append order.

## Interpretation

The results support the claimed data-structure choices. In particular, increasing the card registry from 5,000 to 50,000 did not increase the median card-lookup step count. Queue, stack, and linked-list operations also use a fixed number of pointer/index updates rather than scanning all records.
